# Evidence: proxy body buffering and unbounded download jobs

## 1. /ollama buffers the full request body in memory (no size cap)
status=200 body=b'{"ok":true,"seen":null,"path":"/api/echo"}' elapsed=0.05s sent=5242880
Upstream observed:
{'bytes': 5242880, 'method': 'POST', 'url': '/api/echo'}

Cause: server.ts:238-245 concatenates every chunk into a Buffer before
calling fetch. A 20 GB body, or several concurrent large bodies, can
exhaust the process heap. No Content-Length check or request timeout exists.

POST /api/downloads {"kind":"pull","model":"cap-<n>"} x 6:
dl-352ce236-72fd-4696-9a79-2b86f60165ab running cap-1
dl-2b2cf6c3-429e-4a52-9e86-3ebae108e1b0 running cap-2

dl-00dc354f-4ff1-4588-83cb-eebd9bb941cd running cap-6

Cause: server/downloads.ts has a Map of jobs but no concurrency, queue, or
disk-space admission control. Each job can write up to 20 GB.
